# RNNoise 整网浮点误差分析

分析对象：`examples/rnn_unit.c` 的 `all` 单元与 `examples/rnn_unit.py` 的对应实现。

```
conv1(4→8, tanh) → conv2(8→24, tanh) → gru1 → gru2 → gru3 → concat(96) → dense_out(→2) / vad_dense(→1)
```

报告中每一个数字都由 `scripts/err_stats/` 下的脚本生成，可逐条重跑（见 §7）。

## 1. 术语与度量

### 1.1 两种执行方式

本报告的全部对比都在两种执行方式下进行，二者不能混用（`scripts/err_stats/teacher_force.py` 头部有同样的定义）：

| 术语 | 英文 | 含义 | 本报告中的用途 |
|---|---|---|---|
| **自回归推理** | autoregressive inference (free-running) | 每一步的输出喂给下一步；两个实现各跑各的 | §4.1、§4.4 |
| **教师强制** | teacher forcing | 每一步都喂**参考实现**的真实值，而不是自己上一步的输出 | §4.2、§5.2 |

在自回归推理下，两个实现只有**第 0 帧**输入严格相同（记忆与隐状态初值都是 0，输入是同一份用例）。
从第 1 帧起，两者的中间结果已经不同，因此某一层的差同时包含**该层自身误差**与**上游误差的传播**。
教师强制切断上游传播，把两者分开。

### 1.2 误差度量

对同一层、同一帧、同一分量，记两个实现的值为 $a$、$b$：

$$
\Delta = a - b
$$

| 指标 | 定义 | 说明 |
|---|---|---|
| 最大绝对误差 | $\max\|\Delta\|$ | 在**全部帧 × 全部分量**上取最大值 |
| 平均绝对误差 | $\mathrm{mean}\|\Delta\|$ | 同上样本集 |
| **ULP 倍数** | $\|\Delta\| / \mathrm{ulp}(\max(\|a\|,\|b\|))$ | **必须同时报**，理由见下 |

**为什么必须报 ULP 倍数**：两个 float32 相减，结果只能为 0 或 ≥ 1 ULP，而 ULP 随数值量级变化
（$2^{-26}\approx1.5\times10^{-8}$ 到 $2^{-23}\approx1.2\times10^{-7}$ 差 8 倍）。
只看绝对误差会把"不同层的数值量级不同"误读成"误差沿层增大"。

参考基准：
- `float32` 有 24 位有效位，**正确舍入**（correctly rounded）意味着误差 ≤ 0.5 ULP，因此**1 ULP 已是 float32 能表达的最小非零差**。
- 打印格式 `%.8e` 给 9 位有效数字，恰好唯一确定一个 float32，因此读数据时必须**先还原成 float32**再比较（`err_stat.f32()`）。

### 1.3 环境

| 项 | 值 |
|---|---|
| CPU / OS | x86_64 / macOS |
| C 编译器 | Apple clang 21.0.0 |
| 编译宏 | `-march=native`，实测定义 `__AVX__`、`__AVX2__`、`__FMA__`、`__SSE4_1__` |
| 优化级 | `-O2` |
| Python | 3.12.13 / torch 2.2.2（`torch.set_num_threads(1)`） |

**`-march=native` 影响结论**：`src/vec.h:39` 是 `#if defined(__AVX__) || defined(__SSE2__)` →
`#include "vec_avx.h"`。x86_64 上 `__SSE2__` 恒定义，因此该分支**必然**进入 AVX 实现，
其中除法写成了 `_mm256_rcp_ps`（硬件倒数近似，`src/vec_avx.h` 注释给出上界 1.5×2⁻¹² ≈ 3.66e-04）。
若改为真除法，低精度的数值会变。

## 2. 被测系统与数据流

### 2.1 网络结构与张量形状

规模为真实模型的 //16（`examples/rnn_unit.h` 的 `CASE_*` 宏）。

| 层 | 输入宽 | 输出宽 | 激活 | 备注 |
|---|---|---|---|---|
| conv1 | 12 | 8 | tanh | 12 = 3 帧 × 每帧 4 |
| conv2 | 24 | 24 | tanh | 24 = 3 帧 × 每帧 8 |
| gru1 / gru2 / gru3 | 24 | 24 | sigmoid + tanh | N = 24，门输出拼接宽 3N = 72 |
| dense_out | 96 | 2 | sigmoid | 96 = 24 + 24×3 |
| vad_dense | 96 | 1 | sigmoid | |

### 2.2 数据流与每一个变量的出处

```
用例文件 scripts/unit_cases/
  conv.json  : conv1.inputs(16×4) / conv1.float_weights(12×8) / conv1.bias(8)
               conv2.float_weights(24×24) / conv2.bias(24)
  gru.json   : gru1|gru2|gru3 各含 input_weights_float(24×72) / input_bias(72)
                                recurrent_weights_float(24×72) / recurrent_bias(72)
  dense.json : dense_out.float_weights(96×2) / dense_out.bias(2)
               vad_dense.float_weights(96×1) / vad_dense.bias(1)

第 f 帧的自回归推理：

  ① x_f = conv1.inputs[f]                                (4)
  ② tmp1 = [x_{f-2}, x_{f-1}, x_f]                       (12)   mem = 前两次调用留下的 [x_{f-2}, x_{f-1}]
     conv1.out[f] = tanh( W1 · tmp1 + b1 )               (8)    W1,b1 ← conv.json#conv1
                  ↑ 代码：C `src/nnet.c:114-124`；Python `rnn_unit.py: Conv1D.forward`
  ③ tmp2 = [conv1.out[f-2], conv1.out[f-1], conv1.out[f]] (24)  mem ← 前两次的 conv1.out
     conv2.out[f] = tanh( W2 · tmp2 + b2 )               (24)   W2,b2 ← conv.json#conv2
  ④ gru1: x = conv2.out[f], h = gru1_state (上一帧的自己)
         zrh   = x · W_xzrh + b_xzrh                     (72)   W,b ← gru.json#gru1.input_*
         recur = h · W_hzrh + b_hzrh                     (72)   W,b ← gru.json#gru1.recurrent_*
         zr    = sigmoid( zrh[:48] + recur[:48] )        (48)   z = zr[:24]（更新门）, r = zr[24:]（重置门）
         ĥ     = tanh( zrh[48:] + recur[48:] * r )       (24)
         h'    = z * h + (1 - z) * ĥ                     (24)   → gru1.state[f]
         ↑ 代码：C `src/nnet.c:65-94`（`compute_generic_gru`）
  ⑤ gru2: x = gru1.state[f]        ⑥ gru3: x = gru2.state[f]     （三层共用同一份实现）
  ⑦ dense.in[f] = [conv2.out[f](24), gru1.state[f](24), gru2.state[f](24), gru3.state[f](24)]  (96)
     dense.gains[f] = sigmoid( W4 · dense.in[f] + b4 )   (2)    ← dense.json#dense_out
     vad.out[f]     = sigmoid( W5 · dense.in[f] + b5 )   (1)    ← dense.json#vad_dense
```

隐状态初值：所有 GRU 的初始 state 与所有 conv 的初始 mem 均为 **0**
（C 侧 `memset`，Python 侧 `torch.zeros`；用例 json 里的 `state` 字段两侧都未使用）。

### 2.3 精度档

| 档 | 激活函数实现 | C 侧开关 | Python 侧开关 |
|---|---|---|---|
| 高精度 | `1.f/(1+exp(-x))` / `tanhf`；`torch.sigmoid` / `torch.tanh` | `src/nnet_arch.h:77` 的 `HIGH_ACCURACY`（编译期） | `--acc high` |
| 低精度 | 四阶有理逼近（见 §4.3） | 不定义该宏（默认） | `--acc low`（默认） |

C 侧切档需要重新编译 `src/nnet_default.c`，且 automake 不会因编译选项变化而自动重编，
因此 `collect_all.sh` 在每次切档前 `touch` 该文件，并在运行输出中断言
`[Notice] Now high/low accuracy used` 这一行，否则直接失败退出。

## 3. 单个数值的完整溯源

报告中的每个数值都要能定位到输入。以 §4.1 里 `conv1.out` 那一行的最大误差为例，
完整溯源如下（脚本：`scripts/err_stats/trace_value.py`，可换帧号/分量重跑）。

### 3.1 追踪目标

```
conv1.out  帧 8  分量 5
  Python 打印值 → float32 : -0.18364284932613373
  C      打印值 → float32 : -0.18364286422729492
  |Δ| = 1.4901161194e-08 = 1 ULP
```

`conv1.out` 是整网第一个算出来的量，它的上游只有用例输入，**不依赖任何 GRU 状态**。

### 3.2 逐环节

**① 输入出处**：`scripts/unit_cases/conv.json` → 键 `conv1.inputs`（16 帧 × 4 个数）。

**② 滑动窗口**：conv1 保留最近 2 帧输入作记忆。帧 8 用的是 `inputs[6]`、`inputs[7]`、`inputs[8]`：

| 段 | 出处 | 值 |
|---|---|---|
| mem 前段 | `conv1.inputs[6]` | `[1.0, 1.5, 2.0, 2.5]` |
| mem 后段 | `conv1.inputs[7]` | `[1.0, 1.5, 2.0, 2.5]` |
| 本帧 | `conv1.inputs[8]` | `[1.0, 0.5, 0.5, 1.0]` |

**③ 拼接**：`tmp1 = [x6, x7, x8]`，12 个数，`tmp1[j] = inputs[6 + j//4][j%4]`。

**④ 线性层**：`y = W1 · tmp1 + b1`，只要第 5 个输出：

| j | 输入出处 | tmp1[j] | W1[j][5] 出处 | W1[j][5] | 乘积 |
|---|---|---|---|---|---|
| 0 | `inputs[6][0]` | +1.0 | `float_weights[5]` | +5.3419407457e-02 | +5.3419407457e-02 |
| 1 | `inputs[6][1]` | +1.5 | `float_weights[13]` | −2.3495245725e-02 | −3.5242868587e-02 |
| 2 | `inputs[6][2]` | +2.0 | `float_weights[21]` | +1.7076613382e-02 | +3.4153226763e-02 |
| 3 | `inputs[6][3]` | +2.5 | `float_weights[29]` | +5.3307213821e-03 | +1.3326803455e-02 |
| 4 | `inputs[7][0]` | +1.0 | `float_weights[37]` | −7.7387057245e-02 | −7.7387057245e-02 |
| 5 | `inputs[7][1]` | +1.5 | `float_weights[45]` | −2.9758369550e-02 | −4.4637554325e-02 |
| 6 | `inputs[7][2]` | +2.0 | `float_weights[53]` | +2.0332524553e-02 | +4.0665049106e-02 |
| 7 | `inputs[7][3]` | +2.5 | `float_weights[61]` | −6.8526655436e-02 | −1.7131663859e-01 |
| 8 | `inputs[8][0]` | +1.0 | `float_weights[69]` | +2.0424757153e-02 | +2.0424757153e-02 |
| 9 | `inputs[8][1]` | +0.5 | `float_weights[77]` | −2.3502765223e-02 | −1.1751382612e-02 |
| 10 | `inputs[8][2]` | +0.5 | `float_weights[85]` | +8.4748432040e-02 | +4.2374216020e-02 |
| 11 | `inputs[8][3]` | +1.0 | `float_weights[93]` | −8.4524527192e-02 | −8.4524527192e-02 |
| — | — | — | `conv1.bias[5]` | +3.4746482968e-02 | +3.4746482968e-02 |

权重下标：`float_weights` 的布局是 `[输入 j][输出 i]`，12 行 8 列，所以 `W1[j][5]` 在扁平数组里的下标是 `j*8 + 5`。

**⑤ 求和**：这一步就是那 1 ULP 的出处。

| 求法 | 结果 |
|---|---|
| float64 求和后一次性舍入 | `-0.18575008562766016` → float32 `-1.8575008214e-01` |
| float32 顺序累加（每步舍入） | `-1.8575009704e-01` |

C 侧走 `sgemv`、Python 侧走 `torch.matmul`，**累加顺序不同**，因此落点可能相差 1 ULP。

**⑥ 激活**：`conv1.out[5] = tanh(y[5])`
- 由 float64 参考值算出的 `tanh` 并舍入 = `-0.18364284932613373`
- Python 的打印值 = `-0.18364284932613373` → 与正确舍入值相差 **0 ULP**
- C 的打印值 = `-0.18364286422729492` → 相差 **1 ULP**

### 3.3 结论

这个 `1.490e-08` 不是"某个实现算错了"，而是**线性层累加顺序不同导致结果落在相邻的 float32 上**，
量级就是 float32 的最小可分辨差。§4.1 中高精度一列的全部数值都可以这样溯源，
脚本 `err_all.py` 的 `max|Δ| ÷ ulp` 与 `最大值出现在` 两列给出了每一项的定位。

## 4. 测量结果

### 4.1 2×2 因子对比（自回归推理）

| 项 | 维度 | py高 vs C高 | ULP | py低 vs C低 | py高 vs py低 | C高 vs C低 |
|---|---|---|---|---|---|---|
| `conv1.out` | 8 | 1.490e-08 | 1 | 5.144e-05 | 4.455e-05 | 6.366e-05 |
| `conv2.out` | 24 | 1.490e-08 | 1 | 5.886e-05 | 5.972e-05 | 1.047e-04 |
| `gru1.state` | 24 | 5.960e-08 | 1 | 6.312e-05 | 9.389e-05 | 1.100e-04 |
| `gru2.state` | 24 | 7.451e-08 | 5 | 1.122e-04 | 1.532e-04 | 1.488e-04 |
| `gru3.state` | 24 | 1.192e-07 | 2 | 8.339e-05 | 1.977e-04 | 1.926e-04 |
| `dense.in` | 96 | 1.192e-07 | 2 | 1.122e-04 | 1.977e-04 | 1.926e-04 |
| `dense.gains` | 2 | 2.980e-08 | 1 | 1.314e-05 | 1.380e-05 | 1.687e-05 |
| `vad.out` | 1 | 5.960e-08 | 1 | 1.955e-05 | 1.901e-05 | 3.833e-05 |

四个组构成一个 2×2 因子设计（因子：实现语言、激活精度），每次只变一个因子。

**读法**

1. **高精度组换算成 ULP 后全部落在 1~5 ULP**。不同项的绝对误差从 `1.5e-08` 到 `1.2e-07`，
   差异完全来自各层数值量级不同，按 ULP 看没有系统性增长。
   这正是 float32 舍入量级，说明两个实现在数学上等价。
2. 低精度三个组都在 `1e-05 ~ 2e-04`，比 ULP 量级高约 3 个数量级。
3. `dense.in` 的 `max|Δ|` 等于 `conv2.out`、`gru1/2/3.state` 四者中的最大值
   （`dense.in` 就是它们的拼接；`err_all.py` 抽查 4 组 × 4 帧，16/16 成立）。
4. `dense.gains` / `vad.out` 比 `dense.in` 小一个量级，但**这两个数不是同一个统计量**
   （96 维的 max 与 2 维的 max），直接比较没有意义。逐段实测见下：

   | 段 | 维度 | `max|Δ|` | 相对上一段 |
   |---|---|---|---|
   | `dense.in` | 96 | 1.122e-04 | — |
   | 过 sigmoid 前 `x·W+b` | 2 | 1.931e-05 | 0.17× |
   | 过 sigmoid 后（`dense.gains`） | 2 | 4.798e-06 | 0.25× |

   上表是**把两侧的 `dense.in` 喂给同一个高精度层**得到的纯传播量；
   §4.1 表里 `dense.gains` 的 1.314e-05 还包含最后一层自身的实现差。

### 4.2 逐层误差（教师强制）

把 C 打印出来的每层输入（含上一帧 state）灌给 Python 的同一层，得到该层在**输入完全同源**下的误差。

| 项 | `A_self`（用多项式，对 C 低精度） | `A_swap`（同一批输入，换成 torch 激活） |
|---|---|---|
| `conv1.out` | 5.144e-05 | 4.455e-05 |
| `conv2.out` | 5.731e-05 | 4.533e-05 |
| `gru1.state` | 5.901e-05 | 3.678e-05 |
| `gru2.state` | 8.035e-05 | 3.415e-05 |
| `gru3.state` | 1.063e-04 | 3.032e-05 |
| `dense.gains` | 8.523e-06 | 8.196e-06 |
| `vad.out` | 1.788e-05 | 1.657e-05 |

`A_self` ≥ `A_swap` 在每一项上都成立。高精度组对应的 `A_self` 为 1.49e-08 ~ 1.19e-07（1~2 ULP）。

### 4.3 单算子基准

在 x = −8.00 … +8.00（步长 0.01，1601 点）的固定网格上单独测量激活函数
（`./rnn_unit activation` + `scripts/err_stats/bench_act.py`；网格点由 C 打印、Python 直接读）。

**sigmoid**（参考值 = float32 精确值）

| 实现 | 全网格 `max|Δ|` | 全网格 `mean|Δ|` |
|---|---|---|
| C 高精度 | **0.000e+00** | 0.000e+00 |
| C 低精度（多项式 + `_mm256_rcp_ps`） | 1.446e-04 | 4.346e-05 |
| Python 高精度（`torch.sigmoid`） | 5.960e-08 | 1.463e-08 |
| Python 低精度（`sigmoid_approx`） | 2.933e-05 | 1.685e-05 |

C 高精度在 1601 个点上**逐位**等于 float32 精确值（即正确舍入的结果）。

**tanh**

| 实现 | 全网格 `max|Δ|` | 全网格 `mean|Δ|` |
|---|---|---|---|
| C 高精度 | **0.000e+00** | 0.000e+00 |
| C 低精度 | 2.769e-04 | 6.224e-05 |
| Python 高精度（`torch.tanh`） | 1.490e-08 | 9.307e-12 |
| Python 低精度（`tanh_approx`） | 5.966e-05 | 2.558e-05 |

**刻度分离**。网格是人为铺满 `[−8, +8]` 的，而 sigmoid 的**前置激活**在网络里
（取自 `./rnn_unit gru` 打印的 `gru1/2/3.zrh_recur`，三层 × 16 帧）
只落在 `[−2.68, +2.80]`。两个区间必须分开报：

| 区间 | `Py多项式 − 精确` | `C低 − Py低` | `C低 − torch` |
|---|---|---|---|
| sigmoid 全网格 `[−8, +8]` | 2.933e-05 | 1.385e-04 | 1.446e-04 |
| sigmoid 前置激活区间 `[−2.68, +2.80]` | 2.933e-05 | 9.722e-05 | 1.113e-04 |
| tanh 全网格 `[−8, +8]` | 5.966e-05 | 2.604e-04 | 2.769e-04 |
| tanh（**用 sigmoid 的区间作代理**） | 5.871e-05 | 2.599e-04 | 2.667e-04 |

> 最后一行是代理：tanh 的输入是 `zrh[2N:] + recur[2N:]*r`，**当前没有打印**，
> 所以只能拿 sigmoid 的区间代，不能当作 tanh 的真实输入分布。

**`C低 − Py低` 的含义**。C 与 Python 的低精度用的是**同一套有理多项式**：
`src/vec.h:353` 的 `0.5 + 0.5*tanh_approx(0.5x)` 与 `src/vec_avx.h:426` 的 `sigmoid8_approx`
是同一个函数（把 `u = x/2` 代入、分子分母同乘 16，系数正好是后者的 64 倍，在除法里约掉；
`bench_act.py` 实测两式在 1601 个点上**逐位相同**）。
因此这个差值里多项式逼近误差是**同等的两份、相减即消**，剩下的只可能来自**除法方式不同**：

- C 侧：`_mm256_rcp_ps` 硬件倒数近似（`src/vec_avx.h` 注释给出相对误差上界 1.5×2⁻¹² ≈ 3.66e-04）
- Python 侧：精确除法

实测 `max|C低 − Py低|` = 9.722e-05（sigmoid）/ 2.599e-04（tanh），均在该上界内。

**线性层**：`dense_out`（96→2），float32 与 float64 之差 `max|Δ|` = **5.957e-08（1 ULP）**。

## 5. 误差归因

### 5.1 误差源

| 误差源 | 量级 | 证据 |
|---|---|---|
| tanh 多项式逼近误差 | 单算子、前置激活区间 `max` 5.871e-05（代理区间） | §4.3 |
| sigmoid 多项式逼近误差 | 单算子、前置激活区间 `max` 2.933e-05 | §4.3 |
| C 的 `_mm256_rcp_ps` 硬件倒数 | 相对误差上界 3.66e-04，实测单算子贡献 sigmoid 9.722e-05 / tanh 2.599e-04 | §4.3 |
| 线性层累加顺序 | 1 ULP（`dense_out` 96→2 实测 5.957e-08） | §4.3 |
| float32 舍入（高精度基准） | 1~5 ULP | §4.1 |

**低精度下 `py低 vs C低` 的差 ≈ 纯粹的 `_mm256_rcp_ps` 误差**：
两侧共用同一套多项式，其逼近误差是共有的部分，在相减中抵消（§4.3 的可加性验证）。

### 5.2 误差的增长

定义为 **增长因子** = （自回归推理下的层误差）÷（教师强制下同层误差）。

低精度、两组对比的逐层增长因子：

| 层 | `py低 vs C低`（rcp） | `py高 vs py低`（换激活） |
|---|---|---|
| `conv1.out` | 1.00 | 1.00 |
| `conv2.out` | 1.03 | 1.32 |
| `gru1.state` | 1.07 | 2.55 |
| `gru2.state` | 1.40 | 4.49 |
| `gru3.state` | **0.78** | **6.52** |

**对照实验一：切断隐状态反馈**（`amplify.py: exp_b`）。

把每帧调用 GRU 前的隐状态清零（即去掉跨帧反馈），两侧都是 Python、只换激活：

| 层 | 自回归 第15帧 | 去掉反馈 第15帧 |
|---|---|---|
| `gru1.state` | 9.389e-05 | **4.363e-05** |
| `gru2.state` | 1.405e-04 | **4.759e-05** |
| `gru3.state` | 1.977e-04 | **3.567e-05** |
| `conv1.out` / `conv2.out` | — | **逐值完全相同**（本就没有反馈） |

去掉反馈后误差不再随帧增长，且回落到自回归推理下第 0 帧的水平（4.2e-05 / 4.4e-05 / 3.7e-05）。
`gru1` 的输入 `conv2.out` 不依赖任何 GRU，两种模式下逐值相同，因此它的对比最直接。

**对照实验二：只替换一个激活函数**（`amplify.py: exp_c`）。
以全 `torch` 为基准，分别只把 sigmoid 或只把 tanh 换成多项式：

| 层 | 只换 sigmoid 第15帧 | 只换 tanh 第15帧 | 两个都换 第15帧 |
|---|---|---|---|
| `conv1.out` | **0.000e+00** | 4.455e-05 | 4.455e-05 |
| `conv2.out` | **0.000e+00** | 4.627e-05 | 4.627e-05 |
| `gru1.state` | 1.281e-05 | 9.342e-05 | 9.389e-05 |
| `gru2.state` | 1.830e-05 | 1.506e-04 | 1.405e-04 |
| `gru3.state` | 1.334e-05 | **1.876e-04** | 1.977e-04 |
| `dense.gains` | 6.318e-06 | 7.093e-06 | 1.341e-05 |
| `vad.out` | 1.472e-05 | 8.821e-06 | 5.901e-06 |

`conv1` / `conv2` 只用 tanh，所以"只换 sigmoid"对它们没有影响，差恒为 0 —— 这是该对照的有效性验证。

**在 GRU 隐状态上，增长由 tanh 一侧驱动**（只换 tanh 已经复现几乎全部效果）。
但**到最后一层 `dense.gains` 时两者各占一半**：`6.318e-06 + 7.093e-06 = 1.341e-05`。
原因是最后一层只有 sigmoid、没有反馈，它看到的是从 `dense.in` 传下来的、已经被 tanh 放大的差，
再叠加自己那一层的 sigmoid 逼近误差。

**对照实验三：注入误差的符号方向**（`amplify.py: exp_d`）。

取 `gru1.state` 的 24 个分量，计算每帧的 `mean(Δ)`，把它的符号排成 16 长的序列，做游程检验
（零假设：相邻帧的符号相互独立）：

| 组 | 游程数 | 期望 | z | p |
|---|---|---|---|---|
| `py低 vs C低`（rcp） | 8 | 8.88 | −0.46 | **0.645** |
| `py高 vs py低`（换激活） | 2 | 7.00 | −3.54 | **0.0004** |

rcp 的符号在 16 帧里来回变化（与独立无显著差异）；
换激活的符号从第 4 帧起**连续 12 帧不变**（显著偏离独立）。

**结论**：`_mm256_rcp_ps` 是同一函数两次求值的确定性差，符号逐帧相互独立，
在收缩的反馈中不能相干累积，因此增长因子约等于 1；
激活函数替换改变的是函数本身，偏差方向固定，被反馈逐帧累积，因此增长因子随层数上升。
这与 §4.4 中"rcp 那一组曲线起伏明显、激活那一组平滑上升"是同一件事的两种表现。

## 6. 测试设计评估与结论的适用范围

### 6.1 网络误差分析的标准做法

| 做法 | 本报告是否采用 |
|---|---|
| 2×2（或多因子）对照，每次只变一个变量 | ✅ §4.1 |
| 参考实现逐点对比 + ULP 计量 | ✅ §4.1、§3 |
| **逐层误差预算**（layer-wise error budget）：用教师强制隔离各层贡献 | ✅ §4.2、§5.2 |
| **局部误差注入**（local error injection）：只替换单个算子后观察影响 | ✅ §5.2 对照二 |
| 算子级基准（在固定网格上单独测算子） | ✅ §4.3 |
| 误差的统计刻画（分布、分位数、均值、标准差） | ❌ 只报了 `max` 与 `mean` |
| 输入空间覆盖（多组用例 / 随机信号 / 真实音频） | ❌ 只有 1 组用例、16 帧 |
| 整条链路的输出验证（输入音频 → 输出音频，比对 SNR / 逐样本差） | ❌ 未做（见 §6.3） |

### 6.2 结论能说什么、不能说什么

**可以成立的结论**

1. 高精度档下，C 与 Python 的实现**数学等价** —— 全部指标落在 1~5 ULP 的 float32 舍入量级，
   且每一个数值都能溯源到具体的累加顺序差异（§3）。
2. 低精度档下，`py低 vs C低` 的差**只来自 C 的 `_mm256_rcp_ps`**，
   而不是多项式系数差异 —— 两侧共用同一多项式，逼近误差在相减中抵消（§4.3 的可加性验证）。
3. 误差沿 GRU 层累积的机制是**跨帧隐状态反馈放大方向固定的偏置**，
   由三个对照实验共同支持（§5.2）。
4. 在线性层、softmax 前的线性变换上，累加顺序带来的误差是 **1 ULP** 量级。

**不能成立的结论（以及为什么）**

| 说法 | 为什么不能下 |
|---|---|
| "在任意输入上误差不超过 X" | 样本只有 1 组用例、16 帧。`max\|Δ\|` 是极值统计量，由单个元素决定，换一段输入就会变 |
| "低精度下 C 的误差一定大于 Python" | 实测在 `gru3.state` 上是 0.78×（`py低 vs C低` 反而小于层内注入量），取决于具体输入 |
| "听不出差别" | 只做到阈值层面：VAD 门限与增益台阶的裕量分析（下）。**没有跑完整链路的音频对比** |
| "RNNoise 本身精度足够" | 本报告只比较两个实现是否一致，不评价绝对精度是否满足产品要求 |

关于业务层面的裕量（`scripts/err_stats/business_check.py`，判据取自源码）：

| 对外量 | 实测误差 | 相关判据 | 裕量 |
|---|---|---|---|
| `vad.out` | 1.9e-05 | 判决门限 `> 0.5`（`src/dump_rnn_io.c:173`，且判决在序列级平滑之后） | 本用例 16 帧内离门限的最小距离 7.757e-02；仓库中 500 帧真实音频 dump 内落在门限 ±1.9e-05 的有 0 帧 |
| `dense.gains` | 相对 2.798e-05 | 16 bit 输出的 LSB = 3.052e-05 | 0.92 LSB（−91 dBFS） |
| `dense.gains` | — | 增益限速 `g = MAX16(g, .6*lastg)`（`src/denoise.c:483`） | 该式对第一个参数是 1-Lipschitz，单帧内不会放大已有差 |

即使把单个算子的最坏误差（tanh 全网格 5.966e-05）乘上实测最大增长因子（6.52）得到
≈ 3.9e-04 的保守估计，仍比 VAD 判决的最小裕量 7.757e-02 小约 200 倍。

### 6.3 与标准做法的差距

1. **样本量**。1 组用例、16 帧。所有结论的实际范围是"**在这一组输入、这一套权重、这一台机器上**"。
   要支撑统计意义上的结论，需要多组用例（不同帧数的输入序列）或真实音频。
2. **只用 `max|Δ|`**。`max` 由单个元素决定，建议补p50/p95、标准差或直方图。
3. **没有做完整链路的输出验证**。当前只有"增益的相对误差 0.92 LSB"这一反向推算；
   直接做法是跑两次完整降噪链路输出 PCM，逐样本比对并检查是否跨削波。
4. **没有输入空间覆盖**。用例输入是少数几个固定模式的重复（见 `conv.json` 的 `conv1.inputs`），
   不能代表真实音频的分布。
